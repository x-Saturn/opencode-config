# 推导评审

在终端里逐步展示推导，让用户逐条检查，确认正确后才落盘。目标是去掉"写文件 → 在文件里写评语 → 读文件改文件"的往返。

## 硬规则

1. 用户明确确认（"可以""写吧""定稿"）之前，**不创建、不修改任何文件**。
2. 推导直接输出到对话，不要先写草稿文件。
3. 每个公式块用 `math` 围栏；不要用 `$...$`、`$$...$$`、`\[...\]`。
4. 单字符符号直接写 Unicode（α、∂、∑、∫、≤、→、x²），需要结构时才开块。
5. 编号写在行尾 `\qquad (n)`，不要用 `\tag`。
6. 每块不超过 6 行、约 80 列；多步用 `aligned` 并以 `&` 对齐。
7. 只使用渲染器支持的子集：`\frac`、`\sqrt`、`\sum`、`\int`、`\prod`、`\partial`、`\nabla`、`\cdot`、`\times`、`\left`、`\right`、`\text`、`\overline`、`\hat`、`\vec`，环境 `aligned`、`align`、`cases`、`matrix`、`pmatrix`、`bmatrix`、`gathered`、`array`。不支持的命令会让整块回退成源码。

## 输出形态

```math
\begin{aligned}
f(x) &= \frac{1}{1+e^{-x}} \qquad (1) \\
f'(x) &= f(x)\bigl(1-f(x)\bigr) \qquad (2)
\end{aligned}
```

块与块之间用一句话说明用了什么定理或变换，便于用户指定"第 (2) 步错了"。

## 校验分级

校验脚本：`scripts/verify.py`（相对本 SKILL.md 所在目录），Windows 上直接 `python <skill目录>/scripts/verify.py`。

| 级别 | 触发 | 做法 |
| --- | --- | --- |
| T0 数值抽样 | 每轮推导结束**自动跑一次**，一次调用批量检查所有步骤 | `numeric --check "步号|lhs|rhs" ... --at "x=..."` |
| T1 符号校验 | 出现解方程/不等式、移项变号、代换、带常数积分、行列式、分式化简时**自动追加**，只对高风险步骤 | 同一命令加 `--symbolic` |
| T2 全量 | 只有用户明确要求（"严格验""全验""用 sympy 推"） | 先 T1，仍不确定再升级；注意 simplify 可能很慢 |

T0 调用示例（一条命令检查多步）：

```bash
python scripts/verify.py numeric \
  --check "2|sin(x)**2+cos(x)**2|1" \
  --check "3|(1-x**2)/(1+x**2)**2|((1+x**2)-2*x**2)/(1+x**2)**2" \
  --at "x=0.37,1.91,-1.23"
```

T1 在同一命令基础上加 `--symbolic`；sympy 未安装时脚本会提示并自动跳过，不要因此阻塞。

解集校验：

```bash
python scripts/verify.py solve --step 4 --expr "x**2-4" --roots "2,-2"
```

## 失败处理

- 某项校验失败：不要输出"已完成"。回到该步重算，明确说明错在哪里。
- 同一步连续两次失败：停下来说明卡点，请用户判断，不要继续往下推。
- 校验通过也要如实报告级别，例如"T0 抽样 3/3 通过"，不要说成"已证明"。
- 不要粘贴校验脚本的源码或完整输出；只留一行结论。

## 用户评论后的处理

- 用户指出第 (n) 步有问题：只重算第 (n) 步及其之后，编号保持不变，不要重新编号。
- 用户只问某一步的细节：单独展开该步，不改动其他部分。
- 用户要求换方法：先说明新方法与已确认步骤的衔接点，再重推。

## 定稿

用户确认后才写文件：

1. 用正常 LaTeX 写（文件里可以用 `$$...$$`，不受终端限制）。
2. 只写最终版本，不要保留推导过程中的错误分支。
3. 文件写完后简要报告路径和章节结构。

## 何时不加载本 skill

- 只是顺带提到一个公式，不需要逐步评审。
- 用户明确说"直接写文件"，此时按普通写作流程处理。
